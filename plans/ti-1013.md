  - q: "How does the check run in the background when a CLI exits right after its command?"
    options:
      - "Detached child process: the CLI starts `tix update-check` (hidden) via os.Executable and does not wait"
      - "Goroutine plus a short wait at exit"

`internal/tix/update.go`: cache read/write at `~/.tix/update.json`, strict
`vX.Y.Z` parse and compare (no new dependency; pseudo-versions and
prereleases count as not valid, so dev builds stay silent), and
`FetchLatest(ctx, url)` with a 5s timeout that validates the proxy's
`Version`.

`cmd/update.go`: `resolveVersion` (ldflags, else `debug.ReadBuildInfo`),
`maybeNotify` called from `Execute` before running the command (prints the
notice, records `notified`, and when stale records `checked_at` then starts
`tix update-check` detached), the hidden `update-check` command (fetch, store
latest), and `update` (cached latest or synchronous fetch, `exec.LookPath("go")`,
`go install ...@vX.Y.Z`).

Tests: table tests for parse/compare, cache round-trip, FetchLatest against
httptest (valid, non-semver, failure); notice once/no-repeat/TIX_NO_UPDATE with
a temp HOME and a fresh cache so nothing spawns; `update` with a fake `go` on
PATH recording its args, with an empty PATH, and when current. e2e.sh exports
`TIX_NO_UPDATE=1`.
