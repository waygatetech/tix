Add `max_active` to the projects table (migration) and `Project`, plus
`SetMaxActive(name, n)` and a `tix projects set-max-active` subcommand.
`ClaimNextEvaluated` checks capacity first: it counts in_progress tickets in
the project against `max_active`, then all in_progress tickets against
`TIX_MAX_ACTIVE` (default 3, 0 disables). At either cap it returns an `AtCapacityError` carrying the
waiting tickets. `claim-next` maps that to `exitError{4}` and prints the list.
The check runs outside the claim transaction, so two racing claims can go one
over the cap. A soft cap is fine for pacing agents.
