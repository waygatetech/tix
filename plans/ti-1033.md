This follows ti-1032's sequencing. The code still scans int ids, so this
adds the string-id resolver next to `ResolveRef` without wiring it in.
ti-1034 swaps `ResolveRef` over to it when callers switch to string ids.

- `ShortIDs(ids []string) map[string]string`: strip hyphens, sort, and give
  each id max(4, longest common prefix with either neighbour + 1) chars.
- `resolveUUIDRef(ref) (string, error)`: trim, drop a leading `#`, then split
  off an optional key. A trailing full UUID is split there. Anything else
  splits at the last `-`. The body is lowercased and its hyphens removed. Then:
  - all hex and 4+ chars: match on `replace(id,'-','') LIKE body%`
  - all digits: also match `legacy_id = body`
  - no matches: noSuchTicket. Several: an error with one `<key>-<uuid> <title>`
    line per match. One: run the existing key/project mismatch check.
- Tests apply `uuidMigration` to a seeded database and pin ids with UPDATE to
  force prefix collisions and a digit double match.
