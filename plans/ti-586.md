Queue depth over time already exists: `tix stats --by week` has a QUEUE
column and the web metrics page charts "Review queue depth". No change there.

Add `tix.ReviewQueue(project string) ([]QueueItem, error)` in commands.go:
tickets not done whose cached plan has `review.state == awaiting_review`,
optionally scoped to one project, with `Since` = the latest `plan` event's
`at`, sorted oldest first. The "critique path" is the plan path: it is the
file the human reviews, and tix stores nothing else.

`cmd/queue.go` prints `KEY-ID [tier N] title (project, waiting 3d4h)` plus
the plan path, or JSON. Default scope is all projects, unlike `stale`.
Table-driven test in commands_test.go, one e2e check, README line.
