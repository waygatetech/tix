  - q: "tix done usually runs before the ticket's commit exists (ti-571: done 22:30:43, commit 22:31:39), so HEAD at done is the parent. What SHA does audit treat as the ticket's?"

Ruling: option A (2026-10-08).

`done.go`: before closing, run `git rev-parse HEAD`, `git rev-parse
--abbrev-ref HEAD`, and `git status --porcelain` in repo_path; pass
`{sha, branch, dirty}` as the done event's data via `closeTicket`. No repo_path
or not a git checkout means no data, not a failed done.

`audit.go`: `Audit(ctx, project, days)` — for each project (or the one given)
with a repo_path, load done events carrying a sha, scan `git log --since=<days>
--format=%H%x00%B%x1e` for `This reverts commit <sha>` lines, match recorded
SHAs (per decision above), and record `reverted {sha, revert_sha}` unless the
ticket already has a reverted event for that revert_sha. Returns what it
recorded.

`cmd/audit.go`: `tix audit` with `--project` and `--days` (default 14), prints
one line per new revert, `--json` optional.
