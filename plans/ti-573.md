Rulings: 1 A, 2 A (2026-10-08).

`internal/tix/stats.go`: `Stats(ctx, StatsQuery{Project, Since, By})` loads
`ticket_events` joined to `tickets` (project filter, events with `at >= since`)
and folds per ticket:

- cycle time: first claim → last done, p50/p90 (nearest-rank)
- done_attempt fails per ticket, and counts by `stage`
- blocking findings per ticket and by reviewer from `output.findings` (absent
  when no attempt carried JSON findings)
- reject / reopen / reverted counts, rate = count / tickets done
- tier distribution from the latest plan event's tier; awaiting_review time =
  awaiting plan event → next approve
- weekly buckets (ISO week of event time): done throughput, queue depth =
  tickets awaiting review at week end

`--by tier|concept|week` repeats the summary row per group; concept comes from
the ticket's current plan (`ponytail:` reopened tickets lose it). Text output
is aligned columns; `--json` emits the struct.

`cmd/stats.go`: flags, `--since` accepts `Nd`/`Nw` or a Go duration.
`cmd/web.go` + `cmd/metrics.html`: `/metrics?project=` renders the weekly
buckets as a table plus per-metric SVG polylines; dashboard links to it.
