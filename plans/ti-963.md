`tix.Claim(id)`: `Show`, refuse a status other than `open` by naming it, run
`CheckCapacity` on the ticket's project, then `transitionOpenTicket(id,
"in_progress")`, whose guarded UPDATE settles races and records the `claim`
event.

The status check runs before capacity, not after. Otherwise claiming an
in_progress ticket at capacity would exit 4 and never name its status, which
the acceptance criteria require. Both still run before any write.

`cmd/claim.go` resolves the ref with `tix.ResolveRef`, applies
`requireProjectMatch` like the other ID commands, and calls `tix.Claim`. The
at-capacity reporting and ticket printing in `cmd/claim_next.go` move into
small helpers both commands use, so the exit code and waiting list cannot
drift.

Not changed: Jev evaluation stays on `claim-next`, since naming a ticket is a
human choice. Dependency and lease filtering also stay in `claim-next`'s
picker; `tix plan` still enforces leases.
