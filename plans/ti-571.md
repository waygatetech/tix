`commands.go`: `Reject(id, reason)` moves an in_progress or done ticket to
in_progress and records `reject {reason, from}`. The cached plan stays, so its
leases stay (or come back, for a done ticket); a done ticket's re-acquired
leases go through `checkLeases` in the same transaction so a rejection cannot
double-lease a concept another ticket has planned since. `Reopen(id, reason)`
moves a done ticket to open, clears the cached plan so a re-plan is required,
and records `reopen {reason}`. Both refuse an empty reason.

`cmd/review.go`: `tix reject` and `tix reopen`, each with a required
`--reason` and `--project` match. The MCP server is unchanged.

Not handled: dependents a done ticket unblocked and epics it auto-closed stay
as they are on reject/reopen.
