Split `tix.Add` into `tix.NewTicket(...) (Ticket, error)`, which runs every
check (project resolves, priority 0-5, parent, dependencies) and returns the
ticket that would be inserted (status open/blocked, depends_on, blocked_by),
and the insert. `Add` calls `NewTicket` then writes, so the CLI, web, and
dry-run share one validation path.

`cmd/add.go`: drop the silent priority clamp; `--dry-run` calls
`NewTicket` and prints nothing (or the ticket with `--json`); `--json` after a
real add prints `tix.Show(id)` through `printJSON`. `--dry-run --create`
errors. Tag `ID`, `CreatedAt`, `UpdatedAt` with `omitzero` so the dry-run
ticket carries no id.
