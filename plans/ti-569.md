Migration adds `ticket_events(id, ticket_id, event, at, data)`. It has no FK, so `tix rm` leaves history intact. BEFORE UPDATE and BEFORE DELETE triggers abort, which makes the table append-only at the database level.

`recordEvent(exec, id, event, data)` writes inside the transition's existing transaction. Events are recorded for claim (claimNext and transitionOpenTicket, along with the status), plan (with tier and review state), approve, and done (including epics that close automatically). `Events(id)` reads the timeline, and `tix show --events` prints it.
