`internal/tix/rules.go`: `Rule{ID, Field, Description, Severity}`, `Rules()`
returning the registry (title-required, body-required, priority-range),
`TicketTemplate` const, `RuleError{Rule, Msg}` whose Error() appends
` [id]`, an unexported `violation(id, format, args...)` that panics on an
unregistered id, and `CheckDraft(title, body)` for the title/body checks.

`NewTicket` raises priority-range via `violation`. CLI `tix add` and MCP
`tix_add`/`tix_add_batch` replace their hand-written title/body checks with
`tix.CheckDraft`; enforcement (untrimmed empty-string checks, check order,
MCP priority clamping) is unchanged. The web dashboard's trimmed-title form
check is a UI check and stays as-is.

`cmd/rules.go`: `tix rules` prints the template then `- id (field, severity):
description`; `--json` prints `{template, rules}`. README documents the
command and JSON schema; e2e covers both outputs and rule ids in add errors.
`concepts.yaml` gains `ticket-rules` (module internal/tix/rules.go).
